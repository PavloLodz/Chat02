## Overview

This application provides a chat platform with the following capabilities:

- **User authentication** via JWT
- **Group chat rooms** — public or private, with member management
- **Personal (direct) chats** between users
- **Messages** with optional file attachments
- **Online presence** tracking
- **Role-based access control** (VIEWER, USER, ADMIN, AUDITOR)
- **OpenAPI / Swagger UI** for exploring the REST API

## Getting Started

### Prerequisites

- [Docker](https://www.docker.com/) & Docker Compose (for the recommended path)
- Java 21 + Maven (for local development)
- Node.js (for frontend development)

### Docker Compose (recommended)

Build and start the app along with PostgreSQL:

```bash
docker compose up --build
```

The first build downloads Maven dependencies — subsequent builds are much faster thanks to Docker layer caching.

| URL | Description |
|---|---|
| http://localhost:8080 | Application |
| http://localhost:8080/swagger-ui/index.html | Swagger UI / API docs |

**Stop containers:**
```bash
docker compose down
```

**Stop and remove the database volume (clean slate):**
```bash
docker compose down -v
```

**Start with an empty database** (only seed users, no chat rooms — useful for integration tests):
```bash
docker compose --profile empty-db up --build
```
The empty-db app runs on port **8081**.

### Local Development

Requires a running PostgreSQL instance on `localhost:5432` with the following defaults (configurable in `application.properties`):

| Setting | Value |
|---|---|
| Database | `chat` |
| Username | `chat` |
| Password | `chat` |

**Build and run:**
```bash
# Skip tests for a fast build
mvn clean package -DskipTests

# Run the packaged jar
java -jar target/chat-*.jar
```

**Frontend dev server** (hot reload):
```bash
cd frontend
npm install
npm run dev
```


### Endpoints summary

| Resource | Base path |
|---|---|
| Authentication | `POST /api/v1/auth/login` |
| Users | `/api/v1/users` |
| Chat Rooms | `/api/v1/chat-rooms` |
| Room Members | `/api/v1/room-members` |
| Personal Chats | `/api/v1/personal-chats` |
| Messages | `/api/v1/messages` |
| Attachments | `/api/v1/attachments` |

All protected endpoints require a `Bearer <JWT>` token in the `Authorization` header.

On startup the application seeds the following accounts and rooms:

|---|---|---|---|

| Name | Visibility |
|---|---|
| General | Public |
| Random | Public |
| Announcements | Public |
| Tech Talk | Public |
| Private Lounge | Private |

> Chat room seeding can be disabled by setting the environment variable `APP_SEED_CHAT-ROOMS=false` (used automatically in the `empty-db` Docker profile).

## Frontend

The frontend is a Single Page Application (SPA) built with vanilla JavaScript and bundled with Vite. It communicates with the backend REST API and supports:

- Login & registration pages
- Chat room and personal chat sidebar navigation
- Message area with emoji picker
- Online presence indicators
- File attachment support
- Toast notifications

### Frontend scripts

```bash
npm run dev       # Start dev server with HMR
npm run build     # Production build
npm run preview   # Preview production build
npm test          # Run unit tests (Vitest)
npm run lint      # Lint source files (ESLint)
```

## Configuration

Key application properties (in `src/main/resources/application.properties` or via environment variables):

| Property | Default | Description |
|---|---|---|
| `spring.datasource.url` | `jdbc:postgresql://localhost:5432/chat` | JDBC URL |
| `spring.datasource.username` | `chat` | DB username |
| `spring.datasource.password` | `chat` | DB password |
| `spring.jpa.hibernate.ddl-auto` | `create-drop` | Schema management strategy |
| `app.seed.chat-rooms` | `true` | Whether to seed example chat rooms on startup |

Environment variables override properties using Spring Boot's standard naming convention (e.g. `SPRING_DATASOURCE_URL`).

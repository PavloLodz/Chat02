# Chat

A RESTful chat backend built with **Spring Boot 3** and **Java 21**. It supports group chat rooms, personal (direct) messaging, file attachments, and JWT-based authentication, backed by PostgreSQL.

Generated by Claude.

---

## Features

- **Authentication** — JWT login; stateless, token-based security
- **Users** — registration, profile management, role-based access control
- **Chat Rooms** — public/private group rooms with owner management
- **Room Members** — join/leave rooms; per-room roles (OWNER, MANAGER, MEMBER)
- **Personal Chats** — one-to-one direct messaging
- **Messages** — send, edit, soft-delete; linked to a room or a personal chat
- **Attachments** — file metadata (name, type, size, URL) attached to messages
- **OpenAPI / Swagger UI** — interactive API docs at `/swagger-ui/index.html`

## Getting Started

### Prerequisites

- [Docker](https://docs.docker.com/get-docker/) and Docker Compose — for the recommended path
- Java 21 + Maven 3.9 

### Run with Docker Compose (recommended)

```bash
docker compose up --build
```

The first build downloads Maven dependencies and may take a few minutes; subsequent builds are fast due to Docker layer caching.

| Endpoint | URL |
|---|---|
| API base | http://localhost:8080 |
| Swagger UI | http://localhost:8080/swagger-ui/index.html |

Stop containers:

```bash
docker compose down
```

Stop containers **and** delete the database volume (clean slate):

```bash
docker compose down -v
```

### Run locally (without Docker)

You need a PostgreSQL instance running on `localhost:5432` with the credentials from `src/main/resources/application.properties`:

```
DB: chat  |  User: chat  |  Password: chat
```

Then build and run:

```bash
mvn clean package -DskipTests
java -jar target/chat-0.0.1-SNAPSHOT.jar
```

## Default Seed Users

On startup, the application automatically seeds the following users (created only if they do not already exist):

| Username | Password | Role    |
|----------|----------|---------|
| `viewer` | `vp`     | VIEWER  |
| `user`   | `up`     | USER    |
| `admin`  | `ap`     | ADMIN   |
| `auditor`| `ap`     | AUDITOR |

Use these credentials with `POST /api/v1/auth/login` to obtain a JWT token.

## API Overview

All endpoints are prefixed with `/api/v1`. Authenticated endpoints require an `Authorization: Bearer <token>` header.

| Resource | Path | Notes |
|---|---|---|
| Auth | `/auth/login` | Returns a JWT token |
| Users | `/users` | CRUD; create/delete requires ADMIN |
| Chat Rooms | `/chat-rooms` | CRUD; public/private toggle |
| Room Members | `/room-members` | Add/remove members, assign roles |
| Personal Chats | `/personal-chats` | One-to-one conversation management |
| Messages | `/messages` | Send, edit, delete messages |
| Attachments | `/attachments` | File metadata linked to messages |

Full interactive documentation is available via Swagger UI when the application is running.

## Running Tests

## Configuration

The main configuration file is `src/main/resources/application.properties`. The Docker Compose setup overrides database connection settings via environment variables — no manual editing is needed for the containerised setup.

Key properties:

| Property | Default value |
|---|---|
| `spring.datasource.url` | `jdbc:postgresql://localhost:5432/chat` |
| `spring.datasource.username` | `chat` |
| `spring.datasource.password` | `chat` |
| `spring.jpa.hibernate.ddl-auto` | `create-drop` |

> **Note:** `create-drop` recreates the schema on every restart. Change to `validate` or `update` for persistent data in non-Docker environments.

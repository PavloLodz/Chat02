# chat-api-tests

Black-box REST API test suite for the **Chat** Spring Boot application, built with **REST Assured 5** + **TestNG 7** + **Jackson** + **AssertJ**.

This file was generated by Claude.

---

## Stack

| Library      | Version  | Role                                    |
|--------------|----------|-----------------------------------------|
| TestNG       | 7.10.2   | Test runner & suite orchestration       |
| REST Assured | 5.5.0    | HTTP client / fluent assertion DSL      |
| Jackson      | 2.17.2   | DTO serialisation / deserialisation     |
| AssertJ      | 3.27.3   | Fluent assertions on DTO fields         |
| Lombok       | 1.18.42  | Boilerplate reduction on DTOs           |
| SLF4J Simple | 2.0.16   | Logging backend (pulled in by REST Assured) |

---

## Prerequisites

| Requirement | Version                                              |
|-------------|------------------------------------------------------|
| Java        | 21+                                                  |
| Maven       | 3.9+                                                 |
| Chat app  | Running (with its PostgreSQL database in the Docker) |

The tests are **black-box**: they target a live Chat instance over HTTP and rely on the four accounts seeded by `DataSeeder` at startup (see [Seeded users](#seeded-users)).

---

## Running

```bash
# Default – targets http://localhost:8080
mvn clean test

# Custom base URL
mvn test -Dapi.base-url=http://staging.example.com:9090
```

The test suite is orchestrated by `src/test/resources/testng.xml`. Tests run **sequentially** (no parallel execution) in the order defined there.

## DTO mirrors

The test DTOs in `pl.ldz.chat.dto` are direct equivalents of the source project's records/classes, re-implemented with Lombok and Jackson annotations:

| Test DTO                  | Source DTO                       | Notes                            |
|---------------------------|----------------------------------|----------------------------------|
| `LoginRequestDto`         | `dto.auth.LoginRequestDto`       | Lombok + `@JsonProperty`         |
| `JwtResponseDto`          | `dto.auth.JwtResponseDto`        | `LocalDateTime` deserialiser     |
| `UserRequestDto`          | `dto.UserRequestDto`             | record → Lombok class            |
| `UserResponseDto`         | `dto.UserResponseDto`            | `UUID` + `Instant` fields        |

### Auth (`AuthApiTest`) – 9 tests

**Endpoint:** `POST /api/v1/auth/login`

| Scenario                              | Expected        |
|---------------------------------------|-----------------|
| Valid login – admin / user / viewer / auditor | 200 + token + expiresAt |
| Wrong password                        | 401             |
| Unknown username                      | 401             |
| Blank username                        | 400             |
| Blank password                        | 400             |
| Empty JSON body                       | 400             |

### Users (`UserApiTest`) – 35 tests

**Base path:** `/api/v1/users`

**Authorization matrix:**

| Endpoint           | VIEWER | USER | ADMIN | AUDITOR | anon |
|--------------------|--------|------|-------|---------|------|
| GET /users         | 200    | 200  | 200   | 200     | 401  |
| GET /users/{id}    | 200    | 200  | 200   | 200     | 401  |
| POST /users        | 403    | 403  | 201   | 403     | 401  |
| PUT /users/{id}    | 403    | 200  | 200   | 403     | 401  |
| DELETE /users/{id} | 403    | 403  | 204   | 403     | 401  |

**Scenario coverage:**

- `GET /users` — all roles, no token, malformed token, pagination metadata
- `GET /users/{id}` — all roles, non-existent UUID (404), no token
- `POST /users` — ADMIN creates user (201 + full DTO); VIEWER/USER/AUDITOR get 403; no token; blank username / invalid email / blank password / username > 50 chars get 422
- `PUT /users/{id}` — ADMIN and USER update (200 + updated fields); VIEWER/AUDITOR get 403; no token; non-existent UUID (404); invalid payload (422)
- `DELETE /users/{id}` — ADMIN deletes (204); subsequent GET returns 404; USER/VIEWER/AUDITOR get 403; no token; non-existent UUID (404)

## Configuration

The only configurable property is the target base URL, set as a Maven/system property:

| Property       | Default                 | Description              |
|----------------|-------------------------|--------------------------|
| `api.base-url` | `http://localhost:8080` | Base URL of the Chat instance |

Pass it at runtime:

```bash
mvn test -Dapi.base-url=http://your-host:port
```
